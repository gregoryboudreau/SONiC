| Rev | Date | Change |

## Scope and authority

Healthz is a host service for component assessments, retained events, acknowledgement, and diagnostic archives from any authorized producer. This ownership correction supersedes the older DLDD-specific stream, host `FAULT_INFO` reconciliation, and DLDD-owned archive parts of the 2026-09-26 integration plan. DLDD is one producer; its [HLD](../../device_local_diagnosis/device-local-diagnosis-daemon.md) owns rule evaluation, `FAULT_INFO`, fault reconciliation, vendor queries, action output, and concrete-file handoff. The wire and lifecycle contracts are the [gNOI Healthz v0.3.0 proto](https://github.com/openconfig/gnoi/blob/v0.3.0/healthz/healthz.proto) and [Healthz design](https://github.com/openconfig/gnoi/blob/v0.3.0/healthz/README.md), the version pinned by `sonic-gnmi`, together with [platform health state](https://github.com/openconfig/public/blob/master/release/models/platform/openconfig-platform-healthz.yang) and [platform faults](https://github.com/openconfig/public/blob/master/release/models/platform/openconfig-platform-healthz-fault.yang). The general [gNMI server design](SONiC_GNMI_Server_Interface_Design.md) and [Docker-to-host D-Bus design](../Docker%20to%20Host%20communication.md) define the existing management boundary.

Healthz `Get`, `List`, and `Acknowledge` operate on recorded events; they do not run vendor queries. `Artifact` streams a Healthz-owned archive, possibly waiting within a bounded deadline while packaging completes. Standard `Check` for DLDD components remains `Unimplemented` until a component-specific assessment procedure exists. The nonstandard diagnostic-selector route and reads of old DLDD archives remain separate compatibility paths.

## Architecture and ownership

| Owner | Responsibility |
|-------|----------------|
| Producers, including `sonic-host-services/dldd` | Own their source assessment. DLDD owns complete `FAULT_INFO` rows, startup scan/replay, rule-specific queries and custom logging. It publishes a generic bounded transition on first state and actual changes, reserves an artifact ID before publication when configured, and later submits concrete files. |
| `sonic-host-services/host_modules/healthz.py` | Consume generic transitions without reading `FAULT_INFO`; own source membership, bounded durable event/acknowledgement catalog, component aggregates, stream checkpoint/gaps, bounded archive packaging/storage/retention, and focused D-Bus methods. |
| `sonic-gnmi/gnmi_server/gnoi_healthz*.go` | Implement the gNOI Healthz service: authenticate, validate OpenConfig paths, map host metadata to protobufs, and stream contained host archives. It neither executes vendor commands nor maintains a second catalog. |
| `sonic-mgmt-common/translib` | Map `COMPONENT_HEALTH_INFO` to OpenConfig component `healthz/state` for GET and ON_CHANGE; retain the separate `FAULT_INFO` fault-subtree translation. |

The host module uses Python `sqlite3` under a root-owned `/var/lib/sonic/healthz/` directory. It durably stores events, acknowledgement, generic source membership, component aggregate state, and the consumed stream checkpoint. Host-owned archives live under `/var/lib/sonic/healthz/artifacts/`. Neither gNMI server instance owns this catalog. The gNMI container needs read-only access through its host mount; metadata crosses the existing `sonic_service_client` D-Bus boundary. Vendor commands and ASIC diagnostic shells remain with the source producer on the host. Packaging already collected files is not an on-demand component health assessment.

### Publication, replay, and aggregate state

DLDD replaces `FAULT_INFO` and appends a transition record (no `kind` field) to the generic bounded `HEALTHZ_TRANSITIONS` Redis stream on the first published fault state, including inactive-only local recovery, and every actual status change. The transition has `producer`, `source_key`, stable `transition_id`, `component`, `component_type`, `symptom`, `active` (`1` or `0`), `observed_at` (Unix epoch seconds), and optional `artifact_id` **only for a new reserved archive**. Replay adds `replay=1`; an inactive retained source may add `retain_until` to expire membership without fabricating a clear. A UUID `transition_id` is persisted as `healthz_transition_id` in `FAULT_INFO` with the state and reused for startup replay. A confirmed asserted sample of an already active fault that advances `last_detection_time` appends `kind=observation` with `producer`, `source_key`, `component`, and `observed_at`; this updates `last-unhealthy` without creating an event or changing status/count. Metadata-only refresh preserves the transition ID and creates no event. DLDD owns the complete `FAULT_INFO` scan/replay at startup. The stream has exact `MAXLEN 10000`. DLDD uses Redis `WATCH`/`MULTI`/`EXEC` to write the row and stream together, but an execution-time error inside `EXEC` can leave one write without the other. Exact-source private Redis tests demonstrated missing or duplicate transitions after normal retry, so the strict atomicity contract remains a known deviation.

One bounded host worker consumes transition records idempotently by `(producer, source_key, transition_id)`. It commits event, source membership, acknowledgement-independent aggregate, and stream checkpoint in one SQLite transaction; failed `COMPONENT_HEALTH_INFO` projection retries from the catalog. An observation record is deduplicated by its Redis stream checkpoint; it advances `last-unhealthy` only when that `(producer, source_key)` is currently active for the component and the aggregate is `UNHEALTHY`. Unknown or stale source observations are checkpointed but ignored; no observation inserts an event or changes status/count. The worker republishes known aggregate state after restart without scanning `FAULT_INFO`. The host module exposes `get`, `list`, and `ack` metadata methods through the existing D-Bus server; they take JSON request strings and return an `int32` result code plus a JSON response string. A synchronous maximum-size `submit_artifact` may contend with metadata calls, so latency under concurrent packaging remains a performance qualification gap. An active source creates an `UNHEALTHY` event. A first unhealthy state, or later `HEALTHY` to `UNHEALTHY` transition, increments `unhealthy-count`; overlapping active sources create separate events without another component count increment. Clearing the final active source creates a `HEALTHY` event. A first inactive-only transition creates a `HEALTHY` event without inventing earlier unhealthy history. `last-unhealthy` comes from confirmed asserted observation, never clear time. The projected `COMPONENT_HEALTH_INFO|<URI-escaped component>` row contains `status` and `unhealthy_count`, plus `last_unhealthy` (Unix epoch nanoseconds) when known.

The stream size must cover the supported host-backend outage window, and Redis Stream support must be checked on the target image. If trimming passes the checkpoint or Redis loses unconsumed records, Healthz records a history gap, preserves catalogued events, and never fabricates missing transitions. DLDD can replay only its explicit current `FAULT_INFO` state with its persisted transition ID. If an older event was pruned, replay remains deduplicated against the retained source transition ID; if the catalog itself was lost, replay can establish at most that current observation, not unseen history. A missing or expired row is no proof of recovery, and a complete active/clear cycle may be lost during a longer outage. Healthz never scans or parses `FAULT_INFO`; `COMPONENT_HEALTH_INFO` is published only for components with a known assessment.

The fault `origin_time` remains fixed for the life of a retained row. `last_detection_time` identifies the latest sample that confirmed the underlying condition asserted; a clear observation does not update it. An earlier locally vendored `openconfig-platform-healthz-fault.yang` description included clear time; the vendored model is aligned to this asserted-sample contract for this integration. The health-state YANG defines `status`, `last-unhealthy`, and `unhealthy-count` with ON_CHANGE telemetry.

### Event IDs, artifacts, and retention

The host catalog assigns Healthz event identity once per source transition. A **new** reserved archive ID is both `ComponentStatus.id` and the first `ArtifactHeader.id` when the final regular file exists. Without a new archive, Healthz allocates and persists an opaque `hz-<uuid>` event ID; the producer's `transition_id` is a separate replay key. A retained `INACTIVE` DLDD row may still carry an older archive reference; its recovery event gets a distinct opaque ID and does not advertise that archive again. A late new archive must not silently attach to an existing opaque-ID event with a different first header ID. The older catalog permits this and conflicts with the explicit event ID rule; the migration needs a deliberate disposition. `ComponentStatus.created` records the stored observation time.

The catalog retains events and acknowledgement across service and device restarts within a disk bound. It prunes older events before a component's newest event, preferring acknowledged events within that set, so a retained older event cannot make `Get` contradict the known aggregate. Acknowledgement never deletes an archive. Healthz now owns bounded archive storage under `/var/lib/sonic/healthz/artifacts/`, while the old `/var/lib/sonic/dldd/artifacts/` archive tree remains read-only compatibility. Standard `Get` and `List` advertise an `ArtifactHeader` only while the final regular file exists: no header during pending packaging, a header after atomic no-clobber publication, and no header after garbage collection. A caller that already knows the reserved archive ID, for example from DLDD's native `FAULT_INFO`, may use `Artifact`'s bounded wait while packaging is pending; standard `Get` and `List` do not discover pending artifact IDs. Using the archive ID as the event ID is this design's local convention, not a gNOI proto requirement. The historical event may remain after archive removal. `ComponentStatus.expires` stays unset unless an actual deletion deadline is known. The pinned README recommends removing acknowledged artifacts before unacknowledged ones when reclaiming space; the current host pruning implementation removes the oldest archive at capacity and has not been qualified against that SHOULD-level preference.

The `org.SONiC.HostService.healthz` D-Bus JSON API has `reserve_artifact({})` returning `artifact_id`, `requested_at`, and `location`; new IDs are `healthz-<32 hex digits>.tar.gz`. A producer later calls `submit_artifact({"artifact_id":id,"paths":[{"path":"/absolute/concrete/file","name":"archive/relative/name"}],"metadata":{...}})` with already collected files. Healthz does not run vendor queries or expand rule log globs. Submission packages synchronously, accepts at most 128 files and 64 KiB of JSON, bounds input and archive to 50 MiB, and publishes a staged root-owned mode-0600 archive with atomic no-clobber `os.link` before removing the stage. A durable `.healthz-<uuid>.tar.gz.pending` marker expires after 24 hours; at most 20 archives and pending reservations are held, with oldest-archive pruning at reserve. `artifact_status({"artifact_id":id})` reports `PENDING`, `COMPLETED`, or `MISSING`; idempotent `fail_artifact({"artifact_id":id})` marks a failed reservation without removing a completed archive. DLDD uses these methods to reserve before fault publication, run its own queries in a private temporary stage, submit concrete paths, and clean that stage afterward. Reservation is synchronous and may delay DLDD post-action recheck and fault publication up to its current five-second D-Bus timeout; on failure, DLDD records the request error and publishes without an archive ID. The 20-item/24-hour policy and its interaction with acknowledgement require explicit verification before claiming the README retention preference.

Additive schema migration preserves old SQLite events, acknowledgements, aggregates, and active membership. The new `HEALTHZ_TRANSITIONS` checkpoint starts fresh; any unconsumed tail of old `DLDD_FAULT_TRANSITIONS` is not replayed. Record a conservative one-time migration history gap, then let DLDD's explicit current-state replay use its stable transition ID. Do not invent or duplicate unseen transitions. Existing `dldd-<32 hex digits>.tar.gz` archives remain readable through the contained resolver during migration; new archives are written only to the Healthz directory.

## Standard RPC contract

All path-bearing standard Healthz requests use the complete component path `/components/component[name=X]`, with the component name key. The `healthz` subtree and diagnostic selectors are not part of a standard component path. Healthz protobuf status is an assessment: successful file collection alone cannot establish `STATUS_HEALTHY`. The methods retain existing gNOI authentication and authorization. Read-only gNMI mode permits `Get`, `List`, and `Artifact` reads while gating `Acknowledge` and `Check` as writes.

| RPC | Behavior |
|-----|---------------|
| `Get` | Read the latest stored event for the requested component and include known child statuses only through published OpenConfig platform parent relationships. If only children have events, return a parent wrapper with `STATUS_UNSPECIFIED`, no event ID, `created`, artifact, or acknowledgement, and child statuses in `subcomponents`; this does not assert parent health. Return `NotFound` when neither parent nor children have status. If a component type has no published parent relationship, exact-component retrieval is the tested scope. |
| `List` | Read retained events for the requested component. Exclude acknowledged events by default; include them when `include_acknowledged` is true. |
| `Acknowledge` | Validate path and event ID, idempotently mark that `(component, event)` as acknowledged, and return the updated `ComponentStatus`. It does not delete an artifact. |
| `Check` | Return `Unimplemented` for a standard DLDD component path, with or without `event_id`, until a defined component procedure exists. A future event-specific procedure may add diagnostics but must preserve prior artifacts and derive status from validation, not collection completion. |
| `Artifact` | Stream a contained, allowlisted completed Healthz archive as header, one or more data frames, and trailer. A pending event ID may wait within the existing bound for its final file even when `Get`/`List` omit `ArtifactHeader`. Retain size/SHA-256 metadata and cancellation. Use a basename for `FileArtifactType.name` and `application/gzip` for `.tar.gz`. Resolve new Healthz IDs in the Healthz archive tree and old DLDD IDs in the legacy tree. |

`Get` returns the latest event even when that event has been acknowledged; `List` applies the acknowledged filter. A later recovery event is separate from the earlier unhealthy event, so `List` can retain both while `Get` reports the latest. For a parent `Get`, names are never parsed to invent descendant relationships.

### Legacy diagnostic compatibility

`/components/component[name=X]/healthz/alert-info`, `/critical-info`, and `/all-info` are nonstandard diagnostic selectors. Existing `sonic-gnmi` code accepts them through `Check` and calls host `debug_info.collect`; `Get` does not collect on these paths. Keep this route separate from standard component paths and preserve contained reads of legacy absolute `/tmp/dump` artifacts and old DLDD archives. The diagnostic collector is synchronous while its D-Bus caller has a ten-second timeout. Longer collection needs a separate bounded change. Collection success must not be reported as a healthy component assessment.

The in-repository `sonic-gnmi` tests use a legacy selector and the CLI accepts arbitrary Healthz path JSON. The `sonic-mgmt` port-debug Healthz helper is currently a stub. These sources do not establish whether deployed or external consumers use the selectors; retain compatibility until that question has been checked in the deployed environment.

## Impact and verification

No SAI API change is required. The event catalog, source membership, acknowledgement, and checkpoint survive warm, fast, and cold restarts within retention bounds; Redis loss or stream trimming can still leave a reported gap. The host backend reprojects its durable aggregate after restart. A gNMI container restart does not reset acknowledgement or event IDs.

Focused tests cover generic producer isolation, stable transition ID replay, first active and inactive-only states, overlap, metadata refreshes, stream gaps, aggregate projection, bounded event/archive pruning, and reserve/submit/fail/status methods. RPC tests cover Get/List/Artifact flow, repeat Acknowledge, default filtering, read-only mode, standard Check with and without `event_id`, new and legacy archive containment, and negative paths. Package and DUT checks must establish the Healthz archive read mount, real D-Bus, migration, restart persistence, and acknowledgement-aware retention behavior. The earlier DUT evidence covers the DLDD-specific stream, host `FAULT_INFO` reconciliation, and DLDD-owned archives; it does not qualify this corrected generic boundary or new packaging API. The demonstrated Redis partial-`EXEC` failure and deployed `--noTLS` authorization gap remain open. Do not describe the generic design as deployed until its source, package, and live tests pass.
